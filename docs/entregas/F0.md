# Entrega F0 — Fundaciones

Capturas de la interfaz base, generadas por Playwright (`tests/e2e/specs/quality.spec.ts`) en tema oscuro y claro, a 375 px y 1440 px. Están en `docs/entregas/F0/`.

## Qué se puede hacer

- Registrarse, confirmar el correo, ingresar, recuperar la contraseña, o continuar con Google.
- Activar verificación en dos pasos (TOTP con código QR y códigos de recuperación) y exigirla al ingresar.
- Crear una organización, cambiar de organización, invitar a personas con un rol y quitarlas.
- Ver y cerrar sesiones abiertas; crear y revocar tokens de API con permisos acotados.
- Ejecutar la prueba del sistema y ver el progreso del trabajo en vivo (SSE).
- Instalar la aplicación como PWA. Idioma es-CL/en y tema oscuro/claro/sistema.

## Cómo se verifica

`pnpm check` ejecuta lint (ruff, mypy, ESLint, tsc, reglas de diseño y contrato OpenAPI al día) y todas las pruebas. `pnpm test:e2e` levanta API, worker y web propios y recorre la aceptación de F0:

1. Registro, verificación de correo, ingreso y creación de organización.
2. MFA: activación con un TOTP real, rechazo de código erróneo y anti-replay.
3. Invitación de un lector, que acepta con el enlace del correo.
4. El lector no puede ejecutar acciones de escritura (interfaz deshabilitada y la API responde 403).
5. El propietario ve el progreso de `system.ping` en vivo hasta "Completado".

Además: accesibilidad (axe, WCAG 2.1 AA) en ambos temas, ausencia de desborde horizontal, áreas táctiles ≥ 40 px, foco visible, ningún efecto visual prohibido en el DOM renderizado y validez de la PWA.

## Notas para quien revise

- Los módulos de fases siguientes aparecen en la navegación como no activables.
- El correo en desarrollo sale por la consola de la API (`EMAIL_BACKEND=console`).
- Si el puerto 8000 de tu equipo está ocupado por otro servicio, define `KLICK_API_URL` para el web y el puerto de `pnpm api:dev`.
